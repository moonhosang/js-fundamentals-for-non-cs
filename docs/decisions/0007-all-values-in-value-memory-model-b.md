# 0007. 모든 값을 '값 메모리'에 — 이름표 장부는 이름+화살표만 (model B)

Status: Accepted (supersedes [0006](0006-ledger-and-value-memory-value-in-slot.md); refines [0002](0002-variable-is-alias-not-container.md), [0004](0004-notional-machine-framing.md))

## 맥락
[0006](0006-ledger-and-value-memory-value-in-slot.md)은 **value-in-slot**을 택했다 — 원시값은 이름표 장부 칸 *안에* 값이 직접, 객체만 값 메모리(힙)에. 그런데 실제 위젯을 보니 원시값 슬롯이 `x │ 10`처럼 **이름과 값이 한 칸에 붙어** 나왔다. 사용자 지적: *"이름표 장부와 값 메모리를 분리하랬더니 값이 아직 이름 칸에 붙어 있다 — 일관성이 없다."*

핵심 긴장: value-in-slot은 **표기가 두 가지**였다 — 원시값은 '칸 안 값', 객체는 '칸 안 화살표'. 입문자가 같은 "칸"을 두 가지로 읽어야 했다.

## 결정
**모든 값을 '값 메모리'에 둔다.** 이름표 장부엔 **이름 + 그 값을 가리키는 화살표**만. 표기가 **하나**로 통일된다(변수 = 이름 → 값 셀, 예외 없음).
- **원시값 셀** = 🔒 불변. 대입하면 **각자 새 셀로 복사**(독립). 재할당 = 화살표가 **다른/새 셀로 옮겨감**(옛 셀은 안 고쳐지고 회색).
- **객체 셀** = 가변. 대입하면 **주소만 복사**해 **같은 셀 공유**(별칭).
- const = 이름표의 **화살표를 잠근다**(다른 셀 못 가리킴). 셀 내용과 무관.
- **값 메모리 = 스택 구역(원시값) + 힙 구역(객체)** — M2·M3가 이 물리 구조를 들여다본다(개념 그림은 한 칸으로 그려 일관 유지).

memory-model 위젯: `value:` 슬롯을 **자동으로 이름표 화살표 + 값 메모리 셀(초록·🔒)**로 렌더(`p:frame#name`). 기본 라벨 `📇 이름표 장부 (변수)` / `🗄️ 값 메모리`.

## 결과
- **얻는 것**: 표기가 **하나** — "변수 = 이름 → 값" 그림이 M1~M7 내내 안 흔들린다. 이름/값 분리가 완전해 const·별칭·재할당·`box=null`이 전부 '화살표 사건'으로 설명된다. 반복 각인(입문자 최대 수혜).
- **잃는 것(중요)**: 원시값과 객체가 **둘 다 "이름 → 화살표 → 셀"**로 겉모습이 같아져, *복사 vs 공유의 메커니즘*(원시값=값 자체를 복제 / 객체=주소를 공유)을 그림만으로 못 보여준다 → 규칙화된다.
  - **완화**: 원시값 셀=🔒불변 / 객체 셀=가변으로 표시해 **"가변성이 복사(각자 셀)/공유(같은 셀)를 가른다"**는 상위 원리로 재노출(오히려 0006보다 깊음). 복사=셀 둘, 공유=셀 하나로 **결과는 여전히 눈에 보인다**.
- **물리 정확도**: 작은 정수(SMI)는 실제로 슬롯 인라인이고 원시값은 스택 프레임에 산다 — model B는 이를 단순화. '실제 엔진' 토글/노트로 정직하게 보강([0004](0004-notional-machine-framing.md)).
- **대안(기각)**: value-in-slot(0006) → 표기 이원화로 "이름 칸에 값이 붙어" 분리가 불완전 → 사용자가 반려.
