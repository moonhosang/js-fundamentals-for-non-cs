# 0006. 이름표 장부 │ 값 메모리 두 칸 + 원시값은 value-in-slot

Status: **Superseded by [0007](0007-all-values-in-value-memory-model-b.md)** (원래: Accepted · refines 0002, 0004)

> ⚠️ 이 결정(value-in-slot)은 [0007](0007-all-values-in-value-memory-model-b.md)로 대체됐다. 원시값을 칸 안에 그리니 '이름 칸에 값이 붙어' 이름/값 분리가 불완전했다 → 모든 값을 값 메모리에 두는 model B로 전환. 아래는 역사적 기록.

## 맥락
초기 메모리 시각화는 **값·변수·메모리영역을 한 그림**(RAM 격자)에 결합했다. 그러자 입문자가 답을 못 찾는 질문이 생겼다:
- "const는 뭘 고정하나 — 값? 변수?" · "`box = null`이 힙 객체를 지우나, 변수만 끊나?" · "`let y = x`면 같은 10에 같이 붙나?"
- 원인: **이름(변수)과 값(데이터)을 같은 칸에 섞어** 그려, 둘의 *관계*를 물을 표기 자체가 없었다. 사용자 지적 그대로 — "메모리 영역 자체에 값과 변수를 결합해 설명하니 혼란."

## 결정
메모리 그림을 **두 영역으로 항상 분리**한다.
- **📇 이름표 장부(변수)** — 이름 → (값 또는 주소) 매핑. 스택/변수 영역. (스택 강의는 '📚 스택 (이름표 장부)'로 표기 — M1에서 "스택 = 이름표 장부" 다리 놓음.)
- **🗄️ 값 메모리(힙)** — 객체·배열 등 *묶음*의 실체.

**표기 규칙(불변):**
1. **원시값 = value-in-slot** — 값이 이름표 장부 칸 *안에* 직접. 화살표·힙 박스 없음. (숫자·문자열·불린·null·undefined)
2. **객체 = 포인터** — 장부 칸엔 주소(화살표), 실체는 값 메모리에.
3. **두 칸 항상 노출** — 원시값만 나오는 예시도 값 메모리 칸을 숨기지 않는다(`showHeap:false` 금지). 비어 있으면 *"원시값은 이름표 장부 안에 직접 산다"*로 **반복 각인**.
4. **자물쇠·별칭·GC·재할당은 전부 '장부 쪽 사건'** — const=장부 칸의 주소 고정(값 메모리 내용 아님), 별칭=두 이름이 한 칸을 가리킴, `box=null`=장부 칸만 끊김(값 메모리 객체는 GC 대상), 재할당=칸 내용 교체(값 자체는 불변).

`<memory-model>` 기본 라벨을 이 둘로 고정(콜 스택/힙 아님). "여러 이름 → 한 칸"(별칭)은 `buildNameMap` 헬퍼로 그린다.

## 결과
- **얻는 것**: const·별칭·재할당·`box=null`·불변이 **하나의 표기법**으로 전부 설명된다. 같은 그림이 강의 내내 안 흔들려 반복 노출로 각인 — 입문자 최대 수혜.
- **잃는 것**: 작성이 번거롭다(원시값 예시에도 빈 값 메모리 칸을 늘 그림). 문자열은 엄밀히 힙+주소(엔진)라 value-in-slot은 *단순화* — '실제 엔진' 토글과 심화 카드(개념=복사 / 엔진=공유·interning)로 정직하게 보강([0004](0004-notional-machine-framing.md)).
- **대안(기각)**: ① 한 격자에 결합 → 관계를 못 물음(원래 문제). ② 원시값 예시엔 값 메모리를 숨김 → 표기가 흔들려 각인 실패. ③ 불변을 '변수→값 박스 화살표'로 그림(옛 IMM) → 원시값을 객체처럼 그려 규칙 1과 정면 모순 → value-in-slot으로 통일.
