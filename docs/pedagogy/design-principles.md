# 🎯 강의 설계 규범 (Design Principles)

> 이 문서는 이 프로젝트의 **정체성**이다. 새 강의를 쓰기 전에 반드시 읽는다.
> 규범을 어기는 강의는 "완성"이 아니다.

---

## 0. 뿌리 — 초보자를 롤플레이한다

강의를 쓸 때 **입문자의 머릿속에 들어간다**:
> *"내가 이걸 처음 본다면 — 뭐가 궁금하고, 뭘 착각하고, 뭘 아예 못 볼까?"*

궁극 목표는 지식 전달이 아니라 **사고방식 이식**이다:
> **문법이 아니라 "무엇이 무엇을 가리키나(메모리 모델)"로 생각하게 만든다.**

---

## 1. 초보자의 인식 지도 (Awareness Map) — 가장 중요한 렌즈

모든 설계는 **초보자가 지금 무엇을 보고, 무엇을 못 보는가**에서 출발한다. 세 층으로 나눈다:

| 층 | 무엇 | 예 (변수 개념에서) |
|---|---|---|
| **① 시야 안** | 지금 보이고 이해하는 것 | "변수에 값을 넣는다" (표면 문법) |
| **② 인식의 가장자리** | 어렴풋이 느끼지만 정확힌 모르는 것 | "값이 *어딘가에* 저장되겠지" |
| **③ 인식 밖** | 존재조차 몰라서 **질문조차 못 하는** 것 | 스택/힙, 참조, 스코프, 불변 |

**교수의 핵심 동작 = ③을 ①로 끌어온다.**
초보자가 "궁금해할 줄도 모르는" 것을 **예시·설명·시각화로 드러내** 인식 범위를 넓힌다.
- 👁️ **시각화의 진짜 임무**: 인식 밖에 있는 **안 보이는 것**(메모리·참조·스코프)을 눈앞에 보이게 만들어, 없던 질문을 갖게 한다.
- 🎚️ **조준 거리**: 가장자리 **바로 한 겹 밖**을 겨냥한다. 너무 멀리(인식 밖 저편)를 겨누면 과부하다. (교육학의 ZPD — 근접발달영역.)
- 예: `let money=100; money=200` 은 시야 안. "값 100은 안 변하고, 이름표가 다른 셀을 가리킨다(불변·재할당)"는 인식 밖 → **이름표 → 값 셀 화살표 그림**으로 끌어온다: 재할당은 화살표가 **새 200 셀**로 옮겨가고 옛 **100 셀은 회색**으로 남는다(값 자체는 안 고쳐짐). (모든 값을 값 메모리에 — [ADR 0007](../decisions/0007-all-values-in-value-memory-model-b.md).)

## 2. 강의마다 통과할 7 체크리스트

전 강의가 7개를 다 채우진 않지만, **매번 이 렌즈로 훑는다.**

1. 🧠 **오해 예측·정면 돌파** — "여기서 반드시 밟는 착각은?"을 먼저 묻고 그 강의에서 부순다.
   - 예: 변수=밥통(→이름표), "money=200 변했잖아"(→재할당), 객체=무조건공유(→대입값 타입이 가른다).
2. ❓ **"왜?"를 여러 이유로 깊이** — 규칙만 주지 말고, 규약·수명·효율·안전 등 여러 각도로. "근데 왜?"를 미리 답한다.
   - 예: "왜 스택 칸이 사라져도 괜찮나" → 6가지 이유.
3. 👁️ **시각화(대충 금지)** — 말로 때우지 않는다. 안 보이는 것일수록 필수. 품질·현실성에 신경 쓴다.
   - 예: 매 개념을 `<memory-model>`로. RAM=칸 수십억, 스택=물리적 접시더미.
4. 🌍 **현실 메타포(정확한 것)** — 관념 대신 현실 감각. 단 메타포가 실제와 어긋나면 즉시 바로잡는다.
   - 예: 지갑·효니·가족 계통도. "지폐 한 장은 오히려 참조" 교정.
5. ⌨️ **진짜 도는 코드** — 의사코드·미선언 변수 금지. 그대로 실행되는 유효 코드 + 라이브 실행. `node -e`로 검증.
6. 🔁 **반복 + 점진 드릴** — 난이도 쉬움·보통·어려움 각 5문제(난이도별 페이지). 쉬움은 동일 유형 반복(손 자동화), 어려움은 응용·전이. ([ADR 0008](../decisions/0008-tiered-drills-by-difficulty-files.md))
7. 🔀 **경계·대비로 모델 사고 유도** — 헷갈리는 이웃과 "같은 점/다른 점".
   - 같은 그림 다른 코드 / 같은 코드 다른 그림 / 반대 케이스(객체를 스택에? 원시값을 힙에?). **겉모습 말고 메모리 그림으로 판단하게.**

## 3. 부가 규범

- **실습 배치 — 난이도 3단계(쉬움·보통·어려움 × 5), 난이도별 분리 페이지.** 챕터마다 **쉬움 5 · 보통 5 · 어려움 5 = 15문제**를 **난이도별 3페이지**로. 각 페이지 안에서는 값만 바꿔 **연속 반복(stepped ●○○○○)** — 클릭 피로 없이 손에 붙인다. **쉬움 tier = 동일 유형 반복(automaticity)**, **보통 = 변형·조합**, **어려움 = 응용·전이(경계·함정·다개념)**. 저장은 **난이도별 .js 파일**(`src/drills/easy|normal|hard.js`) → `window.Drills.{easy,normal,hard}[base]`. (규칙: [ADR 0008](../decisions/0008-tiered-drills-by-difficulty-files.md).)
- **문제에 답을 숨겨라 (no answer in the prompt).** 드릴 `ask`에 **정답을 적지 말 것.** 목표만 주고 학습자가 **스스로 도출**하게 한다. — 예: ~~"빈칸에 30"~~ ❌ → "a.money가 100→70이 되려면?" ✓.
- **예측 패턴 (predict-observe-explain).** 값을 내는 문제는 `print((식) === ____)`로 — 학습자가 **비자명한 결과값을 스스로 계산**해 채운다(맞으면 `=== true`). 값 암기가 아니라 실행 모델을 돌려보게 강제. 메모리 챕터는 "바꾼 뒤 **원본이 어떻게 되나**"를 예측(복사=독립 / 참조=공유). (전 26챕터 적용. 감사: 답 노출 231→7, 암기·지시형 103→0.)
- **정답 = 설명 + 증명 (explain on reveal).** `정답` 버튼은 정답 예시 + **💡왜 그런가**(`explain` 없으면 `hint`) + 선택적 **📖개념(`see`) · 📚위키(`wiki`)** 링크를 함께 보인다. `mem`이 있으면 **정답을 봐도 메모리 스텝퍼가 함께 펼쳐진다**(포기해도 '왜'를 보장).
- **정답 시 시뮬레이션 공개 (proof by simulation).** 참조·별칭·전달·GC처럼 노셔널 머신이 요점인 문항은 `mem`(MemoryModel 설정)을 달아, **맞히거나 정답을 보면** '이름표 장부 │ 값 메모리' 스텝퍼로 **왜 그런지 눈으로 증명**한다.
- **표기 일관성 (consistent notation)** — 메모리 그림은 늘 같은 규칙: **이름표 장부(이름+화살표) │ 값 메모리(모든 값 셀) 두 칸**. **모든 값이 값 메모리 셀에 살고, 변수는 화살표로 가리킨다** — 원시값·객체 예외 없이 한 표기(그래야 각인이 안 깨진다). 원시값 셀=🔒불변(대입 시 각자 셀로 복사), 객체 셀=가변(같은 셀 공유). "가변성이 복사/공유를 가른다"를 셀 표시로 재노출. (규칙: [ADR 0007](../decisions/0007-all-values-in-value-memory-model-b.md).)
- **심화는 선택으로** — 이론 심화 챕터는 "선택" 표시 + **건너뛰기** 제공(학습자 자율·속도 존중).
- **값·화면 균형** — 결과를 `print`(값)과 `box`(화면 DOM) 양쪽으로. 시각(눈)으로 확인하는 강점을 살린다.
- **시각 검증** — 개발 중 실브라우저(Chrome 헤드리스) 스크린샷으로 눈으로 확인한다. jsdom은 로직만, 레이아웃·SVG·이모지는 실브라우저로.

## 4. 작성 습관 — misconception-first

코드의 test-first처럼, 강의는 **misconception-first**로 시작한다. 새 강의/섹션 상단에 3줄을 먼저 적는다:

```
// 오해: 여기서 입문자가 뭘 착각하나?
// 왜:   왜 그런가? (여러 이유)
// 대비: 헷갈리는 이웃과 같은/다른 점은?
```

이 3줄을 못 채우면 아직 그 개념을 가르칠 준비가 안 된 것이다.

## 5. Inquiry-Driven Sequencing (의문-사슬) — §1의 '실행 계층'

§1(인식 밖 → 시야 안)을 **매 이음새에서 자동 실행**하는 구조. 개념을 목차 순으로 *나열*하지 말고, **하나를 배우면 자연히 생기는 다음 의문(emergent question)** 을 미리 예측해 **꼬리를 물며** 해소한다. 저자가 목차를 끄는 게 아니라, **학습자의 질문이 다음 단계를 부른다.**

**단위 루프 (각 단계):**
```
[이전에서 생긴 의문을 실습/예측으로 던짐]
  → [마찰: 예상과 다름 (cognitive friction)]
  → [개념·시각화로 해소]
  → [다음 의문이 저절로 생김] ↺
```

**왜** — 학습자가 *스스로* 가진 질문이라 "이걸 왜 배우지?" 갭이 없다(의문의 소유권). 예측→어긋남의 **마찰이 개념을 기억에 박는다**. (정착 용어: inquiry-based learning · predict-observe-explain(POE) · productive failure · desirable difficulty · Socratic sequencing.)

**역할 분담** — "퀴즈여도 실습 위주로":
| 요소 | 역할 |
|---|---|
| **실습·예측** | 사슬의 **엔진** — 의문을 던지고 학습자가 직접 시도(주연) |
| **퀴즈** | 마찰의 **방아쇠** — 예측을 강제해 '어긋남'을 만든다(조연) |
| **개념·시각화** | **해소** (memory-model 등) |
| **종합 드릴** | 끝에서 누적 **숙달** |

**어디에** — 모든 이음새에 강제하면 장황해진다(over-engineering). **마찰이 큰 곳에만 집중.** 예(함수): 매개변수(왜 필요?)·return(왜 print와 달라?)·조기반환(왜 아래가 안 돌아?)이 진짜 friction. 표기법(화살표) 같은 곳은 얕게.

**작성 점검(한 줄)** — 각 단계 앞에서 물어라: *"직전 단계를 배운 학습자가 지금 자연히 갖는 질문은 무엇이고, 이 단계가 그 답인가?"* "아니오"면 순서가 틀렸거나 의문을 **표면화**하지 않은 것이다. (§4 misconception-first의 3줄에 "이전 단계가 남긴 의문" 한 줄을 더해 잇는다.)
