# 이 교재가 특별한 이유 — 그리고 왜 이런 자료가 드문가

> 이 문서는 **positioning(정체성 선언)** 이다. [design-principles.md](design-principles.md)가 "어떻게 만드는가"라면, 이 문서는 "무엇이 남다르고, 왜 시장에 이런 게 거의 없는가"를 정리한다.

---

## Part 1 · 다섯 가지 구별되는 특징

### 1. 하나의 통일된 노셔널 머신 — '이름표 장부(스택) ↔ 값 메모리(힙)'

대부분의 교재는 문법마다 **제각각의 비유**를 끌어다 쓴다(변수는 바구니, 함수는 마법 상자…). 이 교재는 **단 하나의 물리 모델**을 1강부터 5강까지 흔들림 없이 유지한다. ([ADR 0007](../decisions/0007-all-values-in-value-memory-model-b.md) — 모든 값을 값 메모리에)

- **변수**: 값을 가두는 '밥통/상자'가 아니라, 메모리 셀을 가리키는 **이름표(label) + 화살표(wire)**.
- **재할당**: 값이 변신하는 게 아니라, **화살표가 새 값 셀로 옮겨가는 것**(옛 셀은 회색으로 남음).
- **`const`**: 값을 얼리는 게 아니라, **이름표 칸의 화살표를 🔒 잠그는 것**(셀 내용과 무관).
- **스택 vs 힙**: 작은 원시값은 스택 슬롯에, 크고 변하는 묶음(객체·배열)은 힙 창고에 두고 **주소로 연결**.

> **이점**: 참조·별칭·불변성에서 나오는 버그를 *원천 차단*. 문법이 아니라 "무엇이 무엇을 가리키나"로 사고하게 된다.

### 2. 오개념 선제 격파(Misconception-First) + 인과적 꼬리물기

학습자가 한 개념을 배웠을 때 **반드시 품게 될 다음 질문·착각**을 미리 계산해 바로 다음 스텝에 배치한다. ([design-principles §4·§5](design-principles.md) — misconception-first · Inquiry-Driven Sequencing)

- `const` 직후 → `const user = {…}` 인데 `user.name = "지훈"`이 왜 되나? → **포인터 잠금**으로 즉시 해명(1강 ⑤).
- 원시값 복사 직후 → `let y = x`가 "같은 10에 이름표 두 개" 착각임을 **셀 복사 시뮬레이션**으로 파괴(M4-1 2단계).
- 스택 프레임 pop 직후 → "객체를 스택에 뒀다면 함수 종료 시 💥 증발한다"는 **가상 반증**으로 힙의 필연성 증명(M3 ⑤).
- `if` 직후 → `let x = if(...)`의 에러를 **'문 vs 식(값 자리)'** 차이로 규명하며 삼항 연산자의 존재 이유 부여(3-1 ③).

> **이점**: "왜 이러지?"라는 인지적 마찰을 학습자가 겪기 *직전에* 해소 → 질문 낭비 제로. (정착 용어: predict-observe-explain, productive failure, desirable difficulty.)

### 3. 줄글 서술이 아니라 실시간 물리 시뮬레이션(Proof by Simulation)

개념을 추상적 문장으로 때우지 않고, 브라우저 런타임에서 **SVG 베지어 곡선(`buildNameMap`)** 과 **인터랙티브 스텝퍼(`MemoryModel`·`ExprReduce`)** 로 직접 렌더링한다.

- **참조의 증명**: `me.bestFriend.hair = "숏컷"`을 실행하면, 스택의 `hyoni`가 가리키는 힙 아바타가 👩 → 💇‍♀️로 바뀌는 **상태 전이**를 눈으로 확인.
- **그래프 확장**: 1:1 참조 → 배열 목록(G2) → 3대 계통도 트리(G3) → 상호 참조 순환 고리(G4)로 **복합 데이터 구조**를 단계적으로 시각화.

> **이점**: 텍스트 독해 피로 없이 "보이지 않던 것(메모리·참조)"을 눈앞에 세운다.

### 4. 식(Expression)을 '나무 축약(Tree Reduction)'으로 보는 눈

코드를 위→아래로만 읽다 긴 식에서 뇌정지가 오는 비전공자의 고질적 한계를, **컴파일러 AST 축약 모델**로 해소한다.

- **문법 계층 눈금화**: `factor`(원자·호출·괄호) ‹ `term`(`* / %`) ‹ `expression`(`+ -`) 계층을 UI 눈금으로(3-2).
- **Redex 치환**: `(12000 * 3 - 5000) * 1.1` 같은 실무 결제식이 괄호 → 안쪽 → 좌측 우선순위로 **단 하나의 원시값으로 접혀 올라가는 과정**을 단계별 하이라이트로 체화(`ExprReduce`).

> **이점**: 중첩 함수·삼항이 낀 복잡한 한 줄의 독해력 확보.

### 5. 마이크로러닝(쇼츠형 스텝) + 예측 기반 드릴

인지 부하를 극단적으로 통제한다. 한 페이지에 다 쏟지 않고 `3-1~3-6`, `5-1~5-7`처럼 **1개념 = 30초~1분**으로 쪼갠다.

- **즉각적 근육 기억**: 전 26챕터가 **`=== ____` 예측 드릴**을 난이도 3단계(쉬움·보통·어려움 × 5 = 390문제)로. 학습자가 **비자명한 결과값을 스스로 계산**해 손으로 검증하고 넘어간다. ([ADR 0008](../decisions/0008-tiered-drills-by-difficulty-files.md))
- **답을 문제에 숨긴다**: "24 나오게 → 24"(추론 0)를 금지(감사: 답 노출 231→7). 어려움 tier는 `typeof null === "object"`, `0.1+0.2 !== 0.3`, `[3,20,100].sort()[0] === 100`, `1 && 2 === 2` 처럼 **문법을 알아도 틀리는** 함정.
- **예측 → 관찰(시뮬레이션) → 설명**: 참조·전달·GC 핵심 문항은 **맞히거나 정답을 보면** '이름표 장부 │ 값 메모리' 메모리 스텝퍼가 펼쳐져 **왜 그런지 눈으로 증명**된다. `정답`은 설명 + 개념(교재)·위키 링크도 함께.
- **브라우저 계약 테스트**로 전 390 드릴을 real `document`에서 일괄 채점(스텁 드리프트 차단).

> **이점**: 방금 세운 멘탈 모델을 즉시 손으로 검증 → 완강률·정착률 극대화.

## 요약 매트릭스

| 축 | 이 교재의 구현 방식 | 학습자가 얻는 실질 이점 |
|---|---|---|
| **멘탈 모델** | 스택(이름표 장부) ↔ 힙(값 창고) 단일 모델 | 참조·별칭·불변성 버그 원천 차단 |
| **설명 논리** | 오개념 선제 제기 → 인과적 해소 | "왜 이러지?" 마찰·질문 낭비 제로화 |
| **표현식** | AST 계층 기반 안쪽부터 축약 | 중첩 함수·삼항 독해력 확보 |
| **제어 흐름** | 스택 프레임 생명주기(push/pop) | 스코프·클로저·`return`의 물리적 이해 |
| **드릴** | `=== ____` 예측 · 난이도 3단계 · 답 숨김 | 멘탈 모델의 손 검증 → 근육 기억 |
| **전달 매체** | 경량 SPA + 실시간 SVG 인터랙티브 | 줄글 피로 해소 · 완강률 극대화 |

## Part 2 · 왜 이런 자료가 시장에 거의 없는가

### 1. 비대칭적 제작 비용(Asymmetric Authoring Cost)

- **기존 방식**: 마크다운 텍스트 → 코드 캡처 → 출판/녹화 (체감 비용 **1×**)
- **이 방식**: 스택/힙 상태 엔진 구축 → SVG 베지어 좌표 연산 → 인터랙티브 스텝퍼 UI → 가상 반증(💥) 시나리오 코딩 (체감 비용 **30~50×**)

> 플랫폼·출판사 입장에선 이 정도 엔지니어링 투입이 **수지타산에 맞지 않는다.**

### 2. 시장의 단기 성과(Fast-Track) 인센티브 왜곡

학원·부트캠프의 비즈니스 모델은 "2~3주 만에 화면에 그럴듯한 UI 띄우기"에 맞춰져 있다. 메모리 구조·AST 축약 같은 **기초 토목 공사는 당장 눈에 보이는 결과물이 없어**, "진도가 느리고 지루하다"는 이유로 생략되고 "그냥 외워서 쓰세요"로 타협돼 왔다.

### 3. '트리플 유니콘(Triple Unicorn)' 역량의 결핍

설계·구현에 세 역량이 **한 주체에 동시에** 있어야 한다:

1. **아키텍트급 시스템 이해** — 런타임 메모리 할당·렉시컬 스코프·평가 모델의 엄밀한 이해.
2. **탈지식의 저주 + 교육학적 공감** — 자신의 암묵지를 해체하고, 초보자가 '밥통·변신'으로 무너지는 지점을 역추적하는 메타인지.
3. **프론트엔드 구현력** — 머릿속 멘탈 모델을 가벼운 SPA와 반응형 SVG 시뮬레이터로 직접 빌드하는 코딩력.

> 1번을 가진 엔지니어는 고연봉 시스템 설계로 바빠 무료 입문서를 만들 시간이 없고, 2번을 가진 강사는 1번의 깊이가 부족해 나쁜 은유를 답습하며, 3번이 없으면 결국 종이책 줄글로 후퇴한다.

### 4. 지식의 저주(Curse of Knowledge)와 나쁜 은유의 관성

기존 강사는 코드를 볼 때 머릿속에서 도는 스택/힙 시뮬레이션을 **무의식적으로(implicit)** 처리한다. 자신이 *왜* 아는지 분석하지 않은 채, 관습적으로 내려온 "변수는 바구니", "함수는 마법 상자"라는 **오염된 은유를 무비판적으로 복제·재생산**해 왔다.
