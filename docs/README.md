# 📚 문서 허브 — IT 전공자가 아닌 사람을 위한 JS 입문

이 폴더는 이 프로젝트의 **기억**이다. 코드는 "무엇을 하는가"를 담고, 문서는 **"왜 그렇게 하는가"** 를 담는다.
사람이 바뀌고 시간이 흘러도 판단의 근거가 사라지지 않게 한다.

## 어디에 뭐가 있나

| 폴더 | 무엇을 담나 | 언제 읽나 |
|---|---|---|
| **[pedagogy/](pedagogy/)** | 교수 철학·규범 — 이 프로젝트의 심장 | 강의를 쓰기 전에 **반드시** |
| **[architecture/](architecture/)** | 앱이 어떻게 굴러가나 (구조·재사용 위젯) | 코드를 고치기 전에 |
| **[curriculum/](curriculum/)** | 커리큘럼 지도 (챕터·강의·상태) | 무엇을 다음에 만들지 정할 때 |
| **[decisions/](decisions/)** | ADR — 큰 결정과 그 '왜' | "왜 이렇게 했지?"가 궁금할 때 |

## 가장 먼저 읽을 두 문서
1. **[pedagogy/design-principles.md](pedagogy/design-principles.md)** — 모든 강의에 적용하는 설계 규범. 이 프로젝트의 정체성.
2. **[decisions/README.md](decisions/README.md)** — 왜 바닐라인가, 왜 "변수=이름표"인가 등 되돌리기 전에 알아야 할 결정들.

## 문서 관리 원칙 (이 폴더 자체의 규칙)
- **한 문서 = 한 관심사.** 커지면 쪼갠다.
- **결정은 ADR로.** 방향을 바꾸는 판단은 코드가 아니라 [decisions/](decisions/)에 남긴다. 결정을 뒤집을 땐 새 ADR로 이전 것을 **Superseded** 표시(지우지 않는다 — 역사가 곧 근거다).
- **문서는 코드와 함께 고친다.** 구조를 바꾸면 해당 문서도 같은 변경에서 갱신한다. 낡은 문서는 없는 문서보다 나쁘다.
- **평서체 · 왜 중심.** "이렇게 한다"보다 "이래서 이렇게 한다"를 쓴다.
