### 🟩 결론: **약속된 레슨은 전부 구현됨.** ④는 "미완"이 아니라 "아예 안 다룬 개념" 문제.

### 개념 커버리지 갭 (스코프 A로 in/out 판정)
| 개념 | 현황 | A안 판정 | 비고 |
|---|---|---|---|
| **`try/catch` 에러 처리** | ❌ 없음 | 🟨 **갭 후보(강)** | 실무자 매일 씀. repair-drill 문화와 궁합 좋음(에러가 정답인 자리) |
| **`async/await`·Promise** | ❌ 없음 | 🟨 **갭 후보(중)** | 비동기는 실무 필수지만 난이도 큼 → 별도 파트 or 명시적 out 선언 필요 |
| **`JSON.parse/stringify`** | ❌ 없음 | 🟨 **갭 후보(중)** | API 다루는 실무자 필수. 객체(8강)+문자열(builtins-3) 뒤 자연스러움 |
| **구조분해(destructuring)** | ❌ 없음 | 🟨 **갭 후보(중)** | `const {name} = user`·`const [a,b]=arr` 매일 씀. spread(이미 있음)의 형제 |
| **옵셔널 체이닝 `?.`** | ⚠️ 8강서 사용+인라인 설명 | 🟩 **캔버스 stale** | `objects.js:55·149`가 `me.job?.title`을 쓰고 인라인 설명(TypeError 1위 처방). 캔버스 B33은 "미도입"이라 표기 → **캔버스 갱신**(본문=SSOT). 커버리지 자체는 OK(가볍게 도입됨) |
| 부동소수 `0.1+0.2`(B30)·TDZ/호이스팅(B31)·do-while/break/continue(B32) | ❌ 의도적 배제 | 🟩 **유지 타당** | A안에선 심화/관용구 — muted 링크만이면 충분 |

> **판단 필요(당신 몫)**: try/catch·async·JSON·구조분해 4종을 *커리큘럼에 넣을지 / "이건 다음 단계" 명시적 out으로 선언할지*. A안은 "실무자 최적"이라 **최소 try/catch·구조분해는 in이 자연스럽다**[추정]. async·JSON은 별도 파트(확장) 후보.

## ③ 순서 · 의문사슬

### 🟩 총평: 순서 설계는 견고
`map.md`가 2회 재구성 히스토리(just-in-time → 끝몰기 → **파트 내 하위챕터로 녹임**)를 문서화. 함수를 5강으로 당긴 것(배열·map콜백·객체·콜스택의 선수)도 정당. 최상위 파트1~4 + 심화가 제자리(1강 뒤 메모리·5강 뒤 콜스택·8강 뒤 그래프/클래스).

### 🟩 F-SEQ1 [해소·非이슈] 3강 함수호출 선수 역전 — 없음 (확인함)
의심: 3강(표현식, 파트2 · 5강 함수보다 앞)이 함수호출을 축약 예제로 쓰나? → **확인 결과 정상.** 3-4 범위(285–459)엔 사용자 함수 **0개**, `Math.max`(빌트인 블랙박스)만. 사용자 함수(`shippingFee`·`discounted`)는 **3-5에만**, 그리고 3-5는 이미 `🔒 (5강 함수 후)`로 게이트됨. → 선수 역전 없음. (이 항목은 표본 직독으로 반증됨 — false positive였음.)

### 🟨 F-SEQ2 [Info] 레퍼런스(coercion)로의 전방링크
3강 축약·4강 조건이 **뒤에 오는** `coercion`(SSOT)로 링크. 개념그래프 원칙상 정상(집=SSOT, 나머지=링크)이나, **완성/학습 순서상 학습자가 아직 안 본 곳으로 점프**. A안 접근장벽 기준 → 링크에 "뒤에서 자세히" muted 표식 있는지 확인 권장.
